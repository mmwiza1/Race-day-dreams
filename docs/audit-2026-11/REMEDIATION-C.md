## 3. Limitations and notes

- **Race prediction reasons stay in km.** `RacePredictionEngine.kt:81` builds "Recent weekly average N km; longest N km" inside a domain string. That file belongs to Stage B, so the line is reported to the coordinator. Rewriting the joined reason text in the UI would be fragile.
- **Two strength screens still show kg.** These are the Strength analytics volume line and slot editors opened from programme builders other than Gym Now (programme builder, generation, swap). Neither can mislead entry: the field label still says "kg" explicitly. `SharedStrengthAnalyticsScreen` and Android `StrengthAnalyticsScreen` now accept `massUnit`. Wiring it needs a one-line change in navigation, which is outside Stage C: `StrengthNavigation.kt:126` should pass `massUnit = readState().massUnit`, and iOS `AppleAppHost.kt:440` should pass `state.massUnit`.
- **Mid-entry unit change.** A set load typed before the unit is changed in Settings is read in the new unit when it is saved. The unit can only change on another screen, and the field label always shows the active unit.
- **iOS code was not compiled.** The edits are in `AppleRunningToday.kt` (weekly review `imperial` argument) and `AppleGymScreen.kt` (recorded-set text, target text and warm-up unit). They use the same shared APIs that compile for Android.
- **Not run here.** Instrumented tests (no emulator) and screenshot regeneration. The Home countdown, race-day timeline, gym set entry and Strength/Bouldering period pills changed visually and need the canonical screenshot gate.
