## Executive summary

The build is suitable for opt-in development testing. Shared coaching, Gym Now, running execution, history and portability have credible automated coverage. Exact-head tests verify the new rebuild boundary, timed recovery, database upgrade, restore, and key cross-platform paths. The Android implementation is more complete than the iPhone experience. This audit cannot establish outdoor recording accuracy, notification/audio behaviour under real interruptions, full screen-reader usability, or physiological training outcomes.

The highest finding is contradictory marathon readiness advice with no recent evidence (R-01 in the running report). No P0 was reproduced. Storage and explicit activation passed the scenarios exercised. Privacy was reviewed in source and the updater contracts; a physical network capture was outside this audit. Physical testing and the next remediation PR should keep focused on reliability and trust before broadening the feature set.

## Long histories and battery evidence

I constructed pairs of delayed watch/native summaries and checked that each physical run counted once, and that year-old activity left the recent review empty. With 800, 4,000 and 12,000 input rows, the median of 13 warmed-up host JVM observations was **5.83, 10.11 and 17.03 ms** respectively for duplicate grouping plus a weekly review. This was a domain workload without SQLite I/O, GPS samples, Compose, device thermal load or storage pressure; it is unsuitable as an app latency budget.

The coaching read path uses summaries and loads samples for up to 12 eligible recent activities with a 60,000-point cap. History detail has paged summary reads. The snapshot still materialises activities, strength evidence, decisions and plan versions for multiple shared sections. No sustained end-to-end latency, memory, battery or low-storage benchmark was run. Piece 5B adds no independent network polling or recording service. Android update activity is restricted to the official GitHub endpoint and explicit downloads; its network permission is present for that existing optional feature. iOS has no updater or telemetry. ## Findings and priorities

P0 is critical, P1 high, P2 medium and P3 low. Previously documented behaviour is marked as a limitation where the application matches the design.

| ID and severity | Evidence and reproduction | Proposed follow-up |
| --- | --- | --- |
| **A-01 · P1 · Misleading readiness copy** | Five weeks to the marathon, no recent evidence and a target time. The engine returns Not supported but adds a reason saying the plan prepares the runner to finish. Reproduced from the merged domain. [Running report R-01](AUDIT_2026-11_RUNNING_PROGRAMMES.md#findings-and-proposed-remediation) | **First, high impact and small effort.** Correct conditional wording and cover missing-evidence boundaries. Address effective-frequency intensity and overlap evidence separately to keep policy choices reviewable. |
| **A-02 · P2 · iOS returns to a fixed destination and does not restore its current page** | Enter a dated detail from the Calendar and use Back, or terminate while on a deeper screen. The iOS host stores one remembered page, uses fixed back targets, and starts at Home on a fresh host. A draft/interrupted recording can still recover from its own storage. Verified in source and documented parity. [iOS host](../sharedUi/src/iosMain/kotlin/org/racedaydreams/coach/application/AppleAppHost.kt) | **High impact, medium effort.** Add a small restorable stack and test tab → date → detail → Back and restart. Keep explicit recovery prompts and don't restore a sensitive edit without its stored draft. |
| **A-03 · P2 · iOS local-data erasure has fewer controls** | Open Settings and look for Android's confirmed local app-data reset. iPhone Settings supports backup and retention but currently requires deleting the app for a complete reset. Confirmed in the maintained privacy contract. [Privacy](../PRIVACY.md#experimental-iphone-app) | **Medium impact, medium effort.** Parity proposal should include selected-scope wording, active-workout guards, confirmation, staged writes and restore/relaunch coverage. |
| **A-04 · P2 · Health-provider ambiguity and history parity** | Repeated import controls and shared contracts passed; real provider data and permission visibility remain unverified. Cross-provider overlap can classify a separate nested recording as one physical run for totals, retaining both originals. No direct read grant inferred for Apple Health. [Running report R-07](AUDIT_2026-11_RUNNING_PROGRAMMES.md#findings-and-proposed-remediation) | **Medium impact, medium effort.** Prioritise physical verification and expose grouping/provenance in history before changing thresholds. |
| **A-05 · P3 · Narrow app bar elides the brand at 200% text** | Inspect the canonical London Dream Route and storage-preview captures at 200%. “Race Day Drea…” is abbreviated, while its navigation and content controls remain visible. [Dream Route](screenshots/dream-route-large-font.png) · [Storage preview](screenshots/storage-preview-large-font.png) | **Low impact, small effort.** Consider a shorter contextual heading in cramped bars, keeping the full spoken name where appropriate. Check TalkBack and VoiceOver rather than inferring spoken behaviour from pixels. |
| **A-06 · P3 · No physical resource baseline** | Shared computational timing and image review passed, but there is no physical CPU, power or battery data for a long run plus telemetry-free UI use, a closed-screen Gym Now session, or a long retained history. This is a verification gap. | **Medium impact, medium effort.** Measure cold/warm main screen, backup and a 60-minute recording on a mid-range Android device and iPhone. Compare screen off/on, poor signal, BT, headphones and interrupted imports. |

No quality issue listed here was silently fixed or published as an extra release. Remediation should be reviewed and, when approved, done on a separate implementation PR.
