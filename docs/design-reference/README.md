# 0.8.1 design acceptance references

These five JPEGs were supplied by the repository owner for this task. They are
**design references**, never actual-build screenshots or bundled production assets.
Actual renders belong in `docs/screenshots/` and retain source fingerprints.

## Audit of 0.8 (`515fe538`, 23 October 2026)

- Plan: programme metadata occupies most of the first viewport; individual cards
  are tall, only prescribed days are shown, strength is separated from running.
  Target: a seven-day week with compact day/date columns, pale-blue session rows,
  attached support actions and one mint mobility card; metadata behind disclosure.
- Dream: original 0–10 drawing-unit anchors and primitive landmark symbols have no
  meaningful geographic fidelity. Target: legally sourced geographic geometry,
  original offline cartographic treatment, full outline/highlight, percentage and
  distance; retained assignments must not reroll.
- Exercise: 25/174 have guides, using narrow line figures. Target: original human
  illustrations with natural proportions and distinct movement phases, instructional
  equipment and complete canonical coverage. Generating generic guide records does
  not satisfy the artwork gate.
- Routines: small stick figure, paragraphs, concealed mistakes. Target: large blue
  illustration panel, progress, concise dose/instruction, visible mint tip/pink
  mistake and large Back/Next controls.
- Health/shoes/review/trends: exact evidence is valuable but often dominates the
  summary. Target: human-readable summary first, evidence/source disclosure and a
  real labelled weekly chart.
- Live Coach: current engine/control hierarchy is retained; add a legible target
  range visual and keep technical details secondary.

## Release gate (not yet passed)

Capture real API-35 app screens and compare Plan, Dream, RDL, Bench, Walking Lunge
and Ankle Rocks side by side with these references. Check hierarchy, spacing,
blue/navy palette, human illustration quality, cartographic clarity and sunlight/
large-text legibility. Also inspect dark mode and 200% font captures. A source hash
or screenshot consistency test is not design approval. Record remaining differences
honestly in VERIFICATION.md; do not claim this gate from mockups or stale captures.
