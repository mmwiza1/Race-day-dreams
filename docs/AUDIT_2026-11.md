There are no P0 findings. Stored data is well protected:
- recording saves are safe to retry, and only one unfinished run can exist;
- schema migrations only add, and fail safely;
- Health imports roll back if permissions change mid-read;
- restore refuses to run during an active run;
- update verification and secret handling are sound.

The P1 items are about release integrity, cross-zone dating and trust in recorded data.

## Release readiness

`main` is a healthy development build. It is **not** ready for a stable release until:
1. the published Android artefact is non-debuggable (D-3);
2. the version is bumped, for example to 0.15.5, with release notes rewritten through
   `scripts/release-notes.py` (D-1, D-2);
3. the two flaky CI areas are hardened (D-R1, D-R2);
4. the iOS gaps are closed or explicitly documented (D-4);
5. physical acceptance is done, including the Galaxy S24 retest and locked-screen iPhone timing;
6. the owner explicitly authorises a stable tag.
