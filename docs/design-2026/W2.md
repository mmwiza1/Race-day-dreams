# W2 — Plan and Calendar visual modernisation

Presentation only. Scheduling, workout-status semantics, plan data, routes and callbacks are
unchanged. Shared design-system files were not edited; new pieces live in
`sharedUi/.../PlanCalendarComposition.kt` as `internal` components.

## What felt dated

- **Plan:** a plain "Plan" heading over a list of equal tinted cards. There was no sense of the
  block, the phase or progress towards race day. Workout types differed only by text, key sessions
  looked like easy days, and the programme details stacked a card per phase.
- **Calendar:** List/Week/Month were three loose chips above a plain "Training calendar" title.
  Previous/Today/Next were text links. The month grid used letter-in-circle marks in six
  category colours unrelated to the Home week strip, with a thin outline for the selected date and
  a small tint for today. Week rows were small coloured text links inside outlined cards.

## What changed

### Plan
- **Journey header (`JourneyHeader`):** a compact tonal header in the running colour, not an action
  hero. It shows:
  - the race distance as an eyebrow;
  - the single bold "Plan" title, which stays the screen's only "Plan" text;
  - "Week N of M · <current phase>", for the week the athlete is in;
  - a phase track (`JourneyTrack`) built from `plan.phases()` and the plan's start and end dates.
    Each phase is a segment, completed time is solid, the current phase is stronger, today is a
    ringed dot and a flag glyph marks the finish;
  - "Started <date>" and "Race day · <date>", or "Programme ends · <date>" when no race date falls
    inside the plan.
- **This week:** a `SectionLabel` whose caption says "The week you are in" or "Week N of M", over a
  tonal pill navigator. The chevrons keep the "Previous week" and "Next week" descriptions, the
  `weekRangeLabel` text sits between them, and "Current week" is still offered after navigating.
- **Day panels:** one borderless panel per day.
  - The date column shows the weekday over a bold day number; today's number is in a filled
    running-colour disc. The column is read as one phrase, for example "Tuesday 17, today".
  - Glyph discs: runs use `Glyph.RUN` (`Glyph.FLAG` for races) in the running colour, gym sessions
    `Glyph.DUMBBELL` in the strength colour. Completed sessions are filled, planned ones tonal, and
    missed sessions and rest days muted.
  - Days with a long run, quality session or race are tinted in the running container colour, carry
    a "Key session" eyebrow and use a larger, bolder title.
  - Rest days and days with nothing planned are flat and muted.
  - Every action is kept: the run row ("View workout and purpose" with its state description), the
    warm-up and cool-down links, strength rows calling `strength(day)`, the "✓" completion marks,
    "Rest Day", "No session planned" and "Your day, your choice".
- **Programme details:**
  - The dates, version and evidence sit in one borderless panel.
  - The phases are a "Milestones" list (`PhaseMilestone`): a connected marker line where past
    phases are filled, the current one is ringed and labelled "Now · …", and future ones are
    outlined. Each phase keeps its `WhyDetails`.
  - The rebuild dialog and "Edit goal and routine" are unchanged.
- **Empty plan:** a compact `ScreenHeader` ("Your programme" / "Plan") and a borderless panel with
  "Your next chapter" and "Generate my programme".

### Calendar
- **View selector (`ViewSelector`):** a tonal pill with equal List, Week and Month segments. The
  selected segment is filled, shows a check and is exposed as a selected tab; the others show a
  glyph.
- **Header:** a compact `ScreenHeader` ("Month at a glance" or "Week at a glance" / "Training
  calendar") for Week and Month. The List view still shows only the selector and the host's history
  content.
- **Period navigation:** 48 dp tonal chevrons ("Previous month", "Next month", "Previous week",
  "Next week") around a bold period label, plus a tonal "Today" button. At 150% text and above,
  "Today" moves onto its own row.
- **Marks (`SessionMarkShape`):** the Home week strip's language.
  - Shape shows state: completed is filled, planned a ring, moved a dashed ring, and missed or
    skipped a muted ring with a slash.
  - Colour shows discipline: running in the running colour, strength in the strength colour, rest
    neutral. Every mark, including the month grid's, keeps its type letter (E, Q, L, R, S, U, –) in
    every state; the letter is sized from the mark so it fits at any text size.
  - One compact always-visible key line (`CalendarMarkKey`, hidden from screen readers) shows the
    three state shapes and the two discipline colours (as small squares). The letter glossary is
    inside the expandable "Calendar key ⓘ". Month letters are bold and 60% of the mark. Week rows
    already name each workout in full (for example "Long run").
- **Month grid:** sits in a borderless panel.
  - Today's number is in a filled primary disc. The selected date is a tonal tile with a 2 dp
    outline and is exposed as selected.
  - Each cell is at least 56 dp tall and shows up to three marks, then "+n".
  - Each cell speaks its date, "today" and "selected", and every session with its state, in the
    same format as before.
- **Week rows and the day sheet:** each day has a bold heading (today in the primary colour with a
  "NOW" pill read as "Today"), then a borderless panel of rows. Each row has a discipline glyph disc
  and the same plain status text as before, for example "Zone 2 run · 5.0 km · Planned". Rows with
  an action are 48 dp text buttons with a chevron.

### Hybrid same-day Home evidence
- `SharedHomeScreenTest.hybridSameDayShowsRunAndStrengthInTodaysHeroWithTheirOwnRoutes` uses a
  synthetic hybrid state with a planned run and a gym programme session on the same date. It checks
  that both appear inside `today-hero`, with the strength session as the `companion-session`, and
  that each action dispatches its own route.
- `CoachingScreenshotTest.capturesHybridHomeWithRunAndGymSessionOnTheSameDay` saves the next
  version of the seeded gym programme with a session today, for a hybrid user whose long run is
  today. It captures `home-hybrid-same-day` in light mode at 100% text. This capture is
  registered in `UX_REQUIRED`; 522 captures are now required.

## Compromises
- The list view is the host's activity history (`ActivityHistoryScreen` in `app`). It is outside
  this shared screen and was not restyled here.
- Moved, skipped and not-completed sessions no longer show the small "↗ − ?" symbols under month
  marks. Shape now carries those states (a dashed ring for moved, a slashed ring for missed or
  skipped), and every cell still speaks the exact state.
- Category colours (easy green, quality blue and so on) are replaced by discipline colours plus the
  category letter, so the calendar matches the Home strip. Easy and long runs are told apart by
  letter, not hue.
- "Week N of M" in the Plan header now follows the week the athlete is in. The selected week's
  number appears in the "This week" caption when it differs.

## Remaining inconsistencies
- The day sheet opened from the month grid still uses Material's default bottom sheet surface.
- `AdjustmentCard` still uses the older `SemanticCard` tile.
- The `mobility()` slot is host content and keeps its own styling.
